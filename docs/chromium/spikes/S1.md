# S1 native Chromium host

Status: PARTIAL, not GO. CEF `156.0.28+g57389f0+chromium-156.0.8078.88`, source `57389f04a61ab0e9603d9f96602843d0e08bb11c`, verified standard macosarm64 distribution. Standalone source and build instructions are in `Tools/cef/spike/`.

## Passed evidence

- CMake/Ninja built the SwiftUI/AppKit application and five helpers against the pinned distribution.
- The app uses an isolated bundle ID and disposable profile, with CEF sandbox initialization retained and no security-disabling switches.
- Actual runtime reports Alloy style. A local HTML page visibly rendered and completed loading.
- Text input and pasted Hebrew/Japanese appeared in the page. This does not establish IME composition support.
- Native window zoom resized the page from 1100 to 1920 points wide while preserving content and input.
- Browser-close callbacks arrive before the attempted CEF shutdown.

## Unresolved evidence

Two event-only message pumps stalled. Adopting the pinned CEF sample's immediate/reentrant handling and 33 ms one-shot idle fallback restored local page loading. The fallback's energy cost remains unmeasured.

Shutdown after a rendered page still fails: `OnBeforeClose` arrives, then CEF reports `Teardown watchdog expired; recording dump and terminating.` The process exits with code 2 rather than reporting completed shutdown. The sample's bounded ten-iteration drain did not fix it. Native stack/source diagnosis is required before another change.

HTTPS example.com did not finish during the observed window; no certificate validation was bypassed. VoiceOver, real IME composition, trackpad momentum, fullscreen, signing/notarization, clean-account Gatekeeper launch, and performance remain unverified.

The prototype is not production integration. Neither a green build nor a rendered local page completes S1.
