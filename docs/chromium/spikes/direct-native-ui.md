# Retained-tab native UI prototype

`Tools/chromium/ui/BoazHostUI.swift` exports `BoazNativeUIStart` for the prototype C ABI 3. Compile with the root-owned ABI 3 `boaz_host.h` as the bridging header. This packet does not modify the shared header.

The entry validates table size/version and required function pointers, copies the table, registers callbacks, and creates one retained NSWindow with two requested pages. Chromium remains responsible for the application run loop. The UI never calls `NSApplication.run` or terminates the process directly.

SwiftUI supplies native controls around stable NSViewRepresentable instances for the page viewport and NSTextField address entry. The address field is retained and attached through window close; its provider performs no engine call. Page updates never assign address text. The root-owned NativeLocationBar exclusively owns programmatic address updates, per-tab edit save/restore, and revert semantics through UpdateToolbar and OnActiveTabChanged. Swift reads and submits the user-entered field value only, preserving restored uncommitted text even when the field is not being edited.

All engine commands originating from callbacks or UI actions are queued onto main. Ordinary page callbacks copy borrowed UTF-8 state before returning, then update the UI and retrieve borrowed native views after model mutation unwinds. PAGE_CLOSING and PAGE_VIEW_WILL_CHANGE synchronously detach only; they do not call back into the engine. Native views are weakly referenced and reparented into the stable viewport on actual activation. Switching tabs requests activation; it does not navigate or reload a page.

Window/service context is retained by the session until window_closed. NSWindowDelegate denies automatic close and requests coordinated engine closure. Only window_closed releases the visible window. shutdown_ready releases session state after pending window completion. Before-unload cancellation leaves the window alive and displays a cancellation message. Distinct engine page handles identify tabs.

The prototype exposes address navigation, back/forward/reload, add/activate/close tab, close window, and explicit Quit through request_shutdown. A window-scoped local event monitor implements Command-L/T/W/R/Q while native controls have focus; the service callback handles the same commands when delivered from the engine. All engine work remains queued. Native notices are visible SwiftUI text with accessibility labels. Renderer failure and API errors are explicit UI states.

Verification in this packet is source-contract inspection only. Root owns the compile invocation and subsequent runtime check. No engine launch, profile mutation, build configuration, signing, or tests were added. Acceptance still requires successful compilation against the updated ABI, two-page DOM retention, real tab/window IDs, canceled close, native focus/VoiceOver, borrowed-view replacement, and orderly shutdown. This is an isolated prototype, not product completion or the real Boaz application.

Root build entry: `Tools/chromium/build.py --native-ui` compiles the prototype as an arm64 Swift 6 dylib with ABI bridging, using the existing SSD guard and keeping module cache/output on the build image. It does not load the library into Chromium, sign a distribution, or establish runtime acceptance. Run after the currently owned build finishes; the guard refuses concurrent stages.
Swift 6 callback correction: the local event monitor returns only its consumed Bool from `MainActor.assumeIsolated`, then returns the original NSEvent outside that closure. Native view providers return a UInt pointer representation and reconstruct the borrowed pointer immediately in the same synchronous callback. `assumeIsolated` asserts the existing main-actor context; it does not dispatch or transfer AppKit objects between threads. No unchecked Sendable conformance is introduced. Root recompilation remains required.

ABI 3 window preparation creates and retains a native hierarchy synchronously, lays it out, and fills the same complete options table used by explicit creation. It makes no engine calls. The deferred window-created handler finds the retained object by opaque-context equality before binding its real handle and showing it. Unknown contexts are ignored without dereferencing them; zero handles, conflicting handles, and rebinding to another handle are rejected without releasing either window. Duplicate delivery for the same binding is idempotent. Only the explicit initial creation requests the two example pages. Chromium-created windows receive no synthetic tabs, leaving popup contents to Chromium.

The current ABI has no preparation-canceled callback, so a hierarchy prepared successfully but never given a handle remains retained until shutdown; this is an explicit lifecycle gap for the bootstrap to resolve.
