# Folio UI/UX review (iOS, iPhone Duo, macOS, extensions)

**Summary.** The visual language holds together: space gradients, Liquid Glass chrome, the Duo tool rail and the Mac sidebar all look like one product. What keeps it from feeling finished is the basics behind the visuals.
The biggest gaps are on standard iPhones (no visible Back button, an unsafe Clear History, a blank page when a load fails) and in accessibility (the Mac sidebar can't be used with VoiceOver or the keyboard, there are touch targets under 44pt, and the gestures have no alternatives).
Counts: P0 5 · P1 19 · P2 16. Line numbers are from the code as read on 2026-11-09. Mac onboarding is being edited by another agent, so its line numbers may have moved. "Verified" means checked in code; "judgment" is a design call or needs a device check.

Not covered, per the brief: alternate icons, the sign-in step in onboarding, how many tabs the Duo sidebar shows, and favicon fetching (another agent is on favicons).

## P0: broken, or a risk at review

### P0-1 · Small and Lock Screen widgets open the app instead of search, and the circular widget has no container background
- `Apps/Extensions/Widgets/FolioSearchWidget.swift:53-56`, `:70-79`
- Problem 1: `.systemSmall` and `.accessoryCircular` wrap their content in `Link(destination:)`. WidgetKit supports `Link` only in medium and larger families. A small or accessory widget has a single tap target, set with `widgetURL`, so tapping "Search Folio" just launches the app.
- Problem 2: the `.accessoryCircular` branch has no `.containerBackground`. On iOS 17 and later that branch renders the "Please adopt containerBackground API" placeholder on the Lock Screen.
- The circular widget also has no accessibility label.
- Fix:
  - Small: `VStack{…}.widgetURL(FolioLink.search())`.
  - Circular: `ZStack { AccessoryWidgetBackground(); Image(systemName: "magnifyingglass").font(.title2) }.widgetURL(FolioLink.search()).containerBackground(for: .widget) { Color.clear }.accessibilityLabel("Search Folio")`.
  - Keep `Link` only in `.systemMedium`.
- Verified (from WidgetKit's family rules; confirm on device).

### P0-2 · Clear History and Clear Archive erase data in one tap, with no confirmation and no undo; Clear Archive then fires confetti
- iOS: `Apps/iOS/Views/LibrarySheet.swift:65-75` (the button sits in the bottom bar and shows even when the list is empty), confetti at `:68,78`.
- Mac: `Apps/macOS/Views/LibraryViews.swift:55` (toolbar "Clear Archive" with a trash icon).
- Problem: `clearHistory()` and `clearArchive()` run immediately. They're irreversible, the button is in the thumb zone, and celebrating a data wipe reads as a bug.
- Fix:
  - Add `.confirmationDialog("Clear all history?", isPresented: $confirmClear, titleVisibility: .visible) { Button("Clear History", role: .destructive) {…} } message: { Text("This can't be undone.") }`. Use the same on the Mac (`.confirmationDialog` attached to the toolbar button).
  - Disable the button when the list is empty (`.disabled(tab == 0 ? archive.isEmpty : history.isEmpty)`).
  - Remove `.confetti(trigger: archiveClears)`. If you want delight, keep it for constructive moments such as the first pin.
- Verified.

### P0-3 · The Mac sidebar can't be used with VoiceOver or the keyboard
- `Apps/macOS/Views/Sidebar.swift`: `ItemRow` `:384` (`.onTapGesture`), `FavoriteTile` `:171`, `NewTabRow` `:312`, `SpaceDot` `:541`. `HoverIconButton` at `Apps/macOS/Views/BrowserWindow.swift:354-374` has `.help` but no label. `FindBar` buttons at `Apps/macOS/Views/WebPane.swift:83-85` have neither help nor a label.
- Problem: every tab, favorite, space and new-tab row is a view with a tap gesture, not a control. None has the button trait, none can take Tab or Full Keyboard Access focus, and favorite tiles are announced as an unlabeled image. The icon buttons (back, forward, reload, close, find up/down) are announced by symbol name.
- Fix:
  - Turn each of these into `Button { … } label: { row }.buttonStyle(.plain)`. Keep `.onHover`.
  - Add `.accessibilityLabel(title)`, plus `.accessibilityAddTraits(.isSelected)` when active.
  - `FavoriteTile`: `.accessibilityLabel(tab.title ?? host)`.
  - `HoverIconButton`: add `.accessibilityLabel(help)` and make `help` required.
  - FindBar: pass `help: "Previous Match"`, `"Next Match"`, `"Close Find"`.
  - Optionally host the column in `List(selection:)` with `.listStyle(.sidebar)` to get arrow-key navigation and focus rings for free.
- Verified.

### P0-4 · Standard iPhones have no visible Back button (and no Forward anywhere on iOS)
- `Apps/iOS/Views/TabBrowser.swift:285-306` (bottom bar: Tabs, address, Reload, More). Screenshot `iphone-69-2-page.png`.
- Problem: only the Duo's vertical rail has Back (`:206-208`). Every non-Duo iPhone, which is most App Store users, has to know about the edge swipe. Forward isn't reachable on iOS at all (no `forwardList` use in `Apps/iOS`).
- Fix:
  - Put a 44×44 `BarButton(symbol: "chevron.backward")` before the address pill, hidden or disabled when `backList.isEmpty`. Reuse the `Menu { … } primaryAction:` from `backButton` so a long press shows history.
  - Add "Forward" (`chevron.forward`) to the More menu, disabled when `forwardList.isEmpty`.
  - If the bar gets crowded, move Reload into the address pill as a trailing glyph, the way Safari does.
- Verified.

### P0-5 · A failed load leaves a blank page, with no error or retry
- `Apps/iOS/Views/TabBrowser.swift:176-186`, `:161-171`. A search finds no `didFail` or error-page handling in `Apps/iOS` or `Apps/macOS`.
- Problem: offline, DNS failures and TLS errors all leave the page blank and the progress glow simply disappears. WebKit draws no error page of its own, and Safari draws its own.
  - Second risk: `for try await event in page.navigations` exits on the first thrown navigation error. After that, snapshots and the Reader-availability probe stop for the life of the tab.
- Fix:
  - Catch `WebPage.NavigationError` per navigation and store `pageError[tab.id]`.
  - Overlay a `ContentUnavailableView("Can't open this page", systemImage: "wifi.exclamationmark", description: Text(error.localizedDescription)) { Button("Try Again") { page.reload() } }` on the web view, tinted with the space color.
  - Restart the tracking loop instead of letting it end: wrap it in `while !Task.isCancelled { do { for try await … } catch { record; continue } }`.
  - Do the same on the Mac in `TabPane`.
- Judgment (confirm on device how `navigations` behaves when it throws).

## P1: clearly hurts quality

### P1-1 · Home content scrolls under the bottom bar with no edge treatment, and the space dots sit on top of the cards
- `Apps/iOS/Views/ToolRail.swift:37` (`.safeAreaInset(edge: .bottom)`), `Apps/iOS/Views/SpaceHome.swift:26,259-283`. Screenshot `iphone-69-1-home.png`: "BBC News" and "NYT Cooking" show through around the glass bar, and the page dots float over the third row of cards.
- Fix:
  - Replace `.safeAreaInset` with iOS 26's `.safeAreaBar(edge: .bottom)` so the system scroll-edge effect applies, and add `.scrollEdgeEffectStyle(.soft, for: .bottom)` on the `ScrollView` in `SpacePage`.
  - Put the dots in their own glass capsule (`.padding(.horizontal, 8).padding(.vertical, 6).glassEffect(.regular, in: .capsule)`) or inside the bar, not floating 10pt above it.
- Verified in code and screenshot.

### P1-2 · The close button on Today cards is a 24pt target that VoiceOver can't reach
- `Apps/iOS/Views/SpaceHome.swift:360-372`, `:376-383`, used inside the label at `:390` and `:407`.
- Problem: the close `Button` is nested inside the outer card `Button`'s label. The tap target is the glyph plus 6pt of padding (about 24×24pt). VoiceOver merges it into the card, so a card can be closed only through the context menu.
- Fix:
  - Move the close button out of the label: `Button{…}label:{card}.overlay(alignment: .topTrailing) { closeButton.frame(width: 44, height: 44).contentShape(.rect) }`.
  - Add `.accessibilityAction(named: "Close") { model.close(tab) }` and `.accessibilityAction(named: "Pin") { pin() }` on the card.
  - Apply the same fix to `DownloadsView.swift:24`, where a `ShareLink` is nested inside a row `Button`.
- Verified.

### P1-3 · Touch targets under 44pt
- Space dots: `SpaceHome.swift:295-301`, a 6×6pt hit area (18×6 when selected).
- Collapsed host pill: `TabBrowser.swift:278-283`, caption text plus 6pt vertical padding, about 28pt tall.
- Sidebar header Hide button: `SpaceHome.swift:98`, 36×36pt.
- Close on a Today row: `SpaceHome.swift:196`, 36×36pt.
- "Back to pinned page": `SpaceHome.swift:498`, 36×36pt.
- Laptop-pose tab pills: `RootView.swift:223`, about 40pt tall.
- Fix:
  - Dots: keep the visual, add `.frame(minWidth: 24, minHeight: 44).contentShape(.rect)` on each Button. Better, make the strip one element: `.accessibilityElement(children: .ignore).accessibilityLabel("Space").accessibilityValue(current.title).accessibilityAdjustableAction { … }`.
  - Collapsed pill: `.frame(minHeight: 44).contentShape(.capsule)` while keeping the visible capsule small.
  - The 36pt targets become `.frame(width: 44, height: 44)`.
  - Pills: `.padding(.vertical, 12)` plus `.frame(minHeight: 44)`.
- Verified.

### P1-4 · Missing VoiceOver labels, traits and values on iOS
- `HomeMenu` (`SpaceHome.swift:316-323`) has no label, so VoiceOver reads "line.3.horizontal". Fix: `.accessibilityLabel("Menu")`.
- No header traits: space title `SpaceHome.swift:88-91` and "Today" `:137-139`. The only `.isHeader` in the app is in onboarding. Fix: `.accessibilityElement(children: .combine).accessibilityAddTraits(.isHeader)` on the title HStack, and `.isHeader` on "Today".
- Folder rows (`SpaceHome.swift:465-472`) don't expose their expanded state. Fix: `.accessibilityValue(item.isExpanded ? "Expanded" : "Collapsed")` and `.accessibilityHint("Shows or hides the folder's tabs")`.
- The Tabs button (`TabBrowser.swift:216-220`, `:290`) hides the badge count. Fix: `.accessibilityValue("\(tabCount) open")`.
- The address pill (`TabBrowser.swift:292-302`) is read as just the host. Fix: `.accessibilityLabel("Address").accessibilityValue(host).accessibilityHint("Edit address or search")`.
- The search clear button (`Chrome.swift:78`) has no label. Fix: `.accessibilityLabel("Clear Text")`.
- Verified.

### P1-5 · Key gestures have no accessibility alternative and nothing teaches them
- Tab paging by swiping the toolbar: `TabBrowser.swift:120-136`.
- Tucking the rail by swiping: `ToolRail.swift:77-93`.
- Shake to undo: `RootView.swift:33`.
- Space paging: `SpaceHome.swift:17-22`.
- Onboarding teaches none of them (`Apps/iOS/Onboarding/OnboardingView.swift:45-63`), and the "done" page only says "Tap search…".
- Fix:
  - Add `.accessibilityAction(named: "Next Tab") { model.pageTab(by: 1) }` and `"Previous Tab"` on the bar or rail container.
  - Add `.accessibilityAction(named: "Next Space")` and `"Previous Space"` on the home.
  - Add a TipKit `Tip` per gesture, shown with `.popoverTip()` on first use: "Swipe the toolbar to switch tabs" (shown when there are at least 2 tabs) and "Swipe the rail toward the edge to hide it" (Duo only).
- Verified (missing actions); judgment (TipKit).

### P1-6 · The search overlay has no visible Cancel, no escape action and no modal trait
- `Apps/iOS/Views/Chrome.swift:13-15`, `:68-88`.
- Problem: the only way out is tapping the dimmed area, which isn't labeled. VoiceOver's two-finger scrub does nothing, and the page underneath stays reachable.
- Fix:
  - Add a trailing `Button("Cancel") { model.searchTarget = nil }` next to the field, the way Safari does.
  - Add `.accessibilityAddTraits(.isModal)` and `.accessibilityAction(.escape) { model.searchTarget = nil }` on the card.
  - Hide the scrim from accessibility with `.accessibilityHidden(true)`.
- Verified.

### P1-7 · Toasts aren't announced, and Undo expires in 5 seconds
- `Apps/iOS/Views/Chrome.swift:130-145`, `Apps/iOS/App/AppModel.swift:507-513`. The Mac has the same pattern.
- Problem: VoiceOver users don't hear "Tab closed", and they can't reach Undo before it disappears.
- Fix:
  - In `showToast`, call `AccessibilityNotification.Announcement(message).post()`.
  - When `UIAccessibility.isVoiceOverRunning`, use 10s for undo toasts.
  - Add a matching Undo in the More menu ("Reopen Closed Tab") so undo doesn't depend on timing.
- Verified.

### P1-8 · The tab-paging transition slides in from the wrong side
- `Apps/iOS/Views/TabBrowser.swift:87-88`, `:131-134`.
- Problem: `dragX` is set back to 0 in the same `withAnimation` that switches tabs. The new view's `.move(edge: dragX < 0 ? .trailing : .leading)` therefore always reads 0 and becomes `.leading`. "Next" slides in from the left, against the finger. Reduce Motion is also ignored here.
- Fix:
  - Add `@State var pageDirection: Edge = .trailing`, set it from `offset` before calling `pageTab`, and use `.transition(reduceMotion ? .opacity : .asymmetric(insertion: .move(edge: pageDirection), removal: .move(edge: pageDirection == .trailing ? .leading : .trailing)))`.
  - Note: `.id(tab.id)` sits on the view whose `.transition` is being read, so make sure the `.transition` stays after `.id`.
- Verified in code (confirm on device).

### P1-9 · Haptics fire too often
- Every rail collapse and expand while scrolling: `ToolRail.swift:50`.
- Every press-down on every `PressableStyle` control: `Chrome.swift:165`.
- Every space change: `SpaceHome.swift:46`.
- Every sheet open: `RootView.swift:31-32`.
- Problem: the rail one fires constantly while reading. The HIG asks for haptics only at meaningful moments.

  - Drop the sheet haptic.
- Judgment.

### P1-11 · No Find on Page on iOS; on the Mac, Find replaces the whole Edit-menu text group

- Mac: `Apps/macOS/FolioMacApp.swift:116-119` uses `CommandGroup(replacing: .textEditing)`. - Verified.

## P2: polish

### P2-1 · Glass is layered on material, and content cards mix materials
- `Apps/iOS/Views/Chrome.swift:83,86`: a glass capsule sits inside a `.regularMaterial` card, which the HIG advises against.
- `SpaceHome.swift:119,365,446`: `.ultraThinMaterial` and `.regularMaterial` are mixed on one screen.
- Fix:
  - Search card: `GlassEffectContainer { … }.glassEffect(.regular, in: .rect(cornerRadius: 30))`, with the field on a flat `Color.primary.opacity(0.06)` capsule.
  - Content cards: pick one material, either `.thinMaterial` everywhere or a flat `style.background.opacity(0.7)`.
- Judgment.

### P2-2 · Corner radii aren't tokenized
- iOS: 12, 15, 16, 18, 22, 24, 30. Mac: 6, 8, 9, 10, 12, 14, 16.
